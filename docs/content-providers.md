# Initial topic preparation and demo consumption

Creating an authenticated topic prepares its news and overview before the successful creation response. An identical existing title reuses its saved result. Other readers of an in-progress topic poll saved state only; HTTP reads, Home, live topic suggestions, page reloads and returning readers never initiate provider calls. Periodic provider refresh remains deferred. Live discussion uses its own Durable Object rooms and never calls these providers.

## Configuration

Backend secrets live in ignored `apps/backend/.dev.vars` (permissions 0600), never in frontend variables. Configure `SERPER_API_KEY`, `OPENROUTER_API_KEY`, two explicit `:free` model IDs and `CONTENT_PROVIDERS_ENABLED=true`. The primary is `nex-agi/nex-n2.5-mini:free`; the fallback is `nvidia/nemotron-3-super-120b-a12b:free`. Gemma was removed after repeated capacity errors. Mandatory-reasoning models are excluded from this short-output workflow; when the catalogue supports effort `none`, it is explicitly sent along with `enabled: false`. Their presence and zero prompt/completion/request pricing are checked against the live catalogue before inference. If neither remains available for free, fail closed. A missing or disabled configuration never calls providers.

OpenRouter requests have zero maximum prompt, completion and request prices, no tools/plugins, no streaming, a 1,200-token output cap and disabled provider-level fallback. One explicitly reserved free model fallback is allowed after a transient failure or invalid response. A 429 with structured upstream-provider metadata and no platform rate-limit headers can use that single alternative after checking free quota again. Authentication and payment errors open a 24-hour provider cooldown. Unknown/account 429 responses stop the current preparation and open a 15-minute cooldown; a later explicit retry still checks the remaining free allowance before inference. Free-model quota metadata, when reported by the key endpoint, preserves the last ten daily requests. The app's own limits apply even if that metadata is absent. Failed/ambiguous attempts are counted, never refunded automatically.

## Persistent guardrails

| Boundary                     | News (Serper)                | AI (OpenRouter)                   |
| ---------------------------- | ---------------------------- | --------------------------------- |
| Daily installation cap (UTC) | 10 attempts                  | 20 attempts                       |
| Installation lifetime cap    | 100 attempts                 | 200 attempts                      |
| Per-minute installation cap  | 4 attempts                   | 4 attempts                        |
| Per preparation              | 1 search, at most 6 articles | Primary + at most 1 free fallback |

Each account can trigger at most five news searches per UTC day. A topic can be claimed at most twice per UTC day, and retries require an explicit owner/moderator action. Successful topics do not regenerate through that action. A transient preparation error has a minimum 15-minute delay; empty searches and budget pauses wait 24 hours; a transient 429 waits 15 minutes. Retrying AI reuses saved news. Lifetime caps require deliberate administrative review; changing or rotating API keys does not reset them.

Counters and provider reservations live in Postgres and are acquired atomically under row locks before any metered call. All counters survive topic deletion and Worker restarts. A topic lease prevents duplicate concurrent preparation, lasts three minutes and allows explicit recovery after expiry. A stale job cannot overwrite a new job's results. This is not an exactly-once guarantee for external providers: network ambiguity is accounted for conservatively and consumes its reserved attempt.

Moderators can open **Content usage & limits** at `/moderation` to see application attempt counts and pause/resume new content. This is not the remote provider's remaining credit balance, and pausing does not cancel a request already sent. There is no automatic top-up, paid fallback or limit increase in the application.

## Sources and display

Serper supplies titles, URLs, short excerpts and optional images. Duplicate URLs and unsafe/non-public link destinations are rejected. The backend reads a bounded amount of public article HTML only for image metadata; article HTML is never passed to the AI. AI receives at most six titles and 600-character excerpts per source; it does not read full articles. Its output must be complete structured JSON, with two or three short paragraphs and references only to supplied source numbers. Invalid citations and truncated responses are rejected. Factual correctness still needs human evaluation: format validation is not fact checking.

News is saved before inference. The generated overview, public source links, exact original input excerpts, model ID and input hash are retained as a fixed snapshot. Only public content is exposed; provider credentials, author identity, claims, ledger entries and internal inputs are excluded from public projections. Each article exposes its original publication timestamp when available. Relative second/minute/hour/day/week labels are converted into an estimate anchored to the saved retrieval timestamp, displayed with ≈ and an estimated-date tooltip; these are not presented as exact publication times. Unparseable labels remain visible, and missing dates are explicitly unavailable. The summary exposes the model ID saved with that generation, independent of current provider configuration. If sources are empty or a service fails, the UI explains the incomplete state and preserves any available articles.

## Testing and interview preparation

Automated tests use fixtures and transactionally isolated database records, not external searches or inference. Playwright's own server sets `AUTOMATED_TEST_MODE=true`, which overrides enabled provider settings. The real-catalogue browser test also refuses to create against a reused preview that reports live providers enabled. Do not run provider smoke tests as part of CI.

For a real smoke test, use one meaningful topic and inspect the attempt counters before and after. Validate the resulting text and source links, then reload the topic and check that counters remain unchanged. Keep this genuinely generated topic in the database for the interview: showing it again does not depend on remaining provider quota. Start Docker/local Supabase before the demo and preserve its existing volume (`db:stop` preserves data); do not reset the database or remove Docker volumes.

Free-model availability and account-wide usage elsewhere are outside this application's control. A newly created topic can therefore be partial during a provider outage, while an already completed topic stays readable from the database. Remote staging and periodic refresh coordination remain separate work; live discussion is described in [its own guide](realtime.md).

### Local provider validation

Local smoke checks have produced persisted articles and summaries with linked sources. Reloads reuse the stored content without increasing the provider attempt ledger. Transient model failures preserve the articles and use only the bounded explicit retry policy. Provider counters can lag and are never used to refund local reservations. Local database identifiers and individual smoke-test recovery history are intentionally omitted from the published repository documentation.

Topic loading retains the card position and reserves the image frame even when a thumbnail fails. Repeated content/image entrance fades have been removed. Public Home data and up to twelve topic snapshots are cached in session storage for up to thirty minutes, including across the static Mission page; background reads revalidate them without clearing visible content. A 404 evicts the topic, and local topic deletion also removes cached Home entries. Link hover/focus can prefetch stored topic content; these GET requests never generate content. Offscreen scroll reveals still use the shared reduced-motion-aware implementation. Browser tests cover navigation through Home/Mission, delayed revalidation, cache eviction, failed images, attribution/dates, desktop/mobile layout and the retry button becoming available after a cooldown without automatically requesting inference.

### Administrator overview edits and lead photos

Administrators see a pencil immediately before the discussion icon on a generated overview. Title, paragraphs and citations can be edited inline; Save persists them, Cancel discards the draft. PATCH `/api/topics/:id/overview` uses the authenticated JWT and the moderator-only `edit_topic_overview` database function. An expected revision prevents lost updates. Original AI text is retained privately on the first edit; generation date, model, source snapshot and input hash remain unchanged. Readers see the original model followed by “edit by admin”. No provider call is made by the editor.

Initial preparation discovers images for all six returned articles without a publisher allowlist. It prioritizes Open Graph, Twitter and article JSON-LD metadata; when those are absent it inspects responsive images within the article/main element. It preserves signed CDN URLs and supports relative URLs, HTML entities, extensionless image services and browser-decodable formats. Up to six alternatives are saved with each article. Explicit article metadata takes precedence over inline avatars and related-story photos.

Requests use credential-free HTTPS only, public DNS preflight checks for both IPv4 and IPv6, validation on every redirect (at most two), a six-second deadline and a 1 MiB HTML ceiling per article. Image CDN hostnames also require public DNS. No scripts run, no cookies or application credentials are forwarded, no paywalls/challenges are bypassed, and no enrichment runs on reads. DNS preflight is defense in depth rather than DNS pinning; production should retain Workers' public outbound network isolation and must not attach private-network bindings to this fetch path.

The browser decodes each candidate before revealing it, requires at least 640×360 pixels, and tries the next candidate after an error, insufficient resolution or an eight-second load timeout. When a publisher has no usable image, the next article with a photo becomes the lead; the photo always remains paired with its own headline and attribution. If every source fails, news remains readable with a neutral placeholder or text-only layout. Images are not fabricated. JPEG, PNG, WebP, AVIF, GIF and SVG decoding, extensionless URLs, low-resolution rejection and fallback between articles are covered by desktop/mobile browser tests. Unsupported browser formats, inaccessible sites, expired URLs, missing metadata and sources offering only small images cannot be guaranteed a photo.
