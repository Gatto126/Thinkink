# Security

Thinkink is an unreleased prototype. Authentication, database access policies, moderation, provider budgets, topic quotas, comments and daily-deduplicated visits are implemented and covered by local tests. Live rooms are not implemented; discussion refresh uses visible-page polling. Only the current development branch is maintained; there is no supported production release.

Do not include credentials, private records or exploitable vulnerability details in public issues or pull requests. When the repository is hosted on GitHub and private vulnerability reporting is enabled, use **Security → Report a vulnerability** to contact the maintainer privately. That channel has not been configured by this local scaffold. Until a private channel is available, a public request for a private contact must contain no sensitive details.

Before public contributions are enabled, the maintainer should configure that private reporting channel. Reports should identify the affected commit, expected and actual behavior, and a minimal reproduction using synthetic data. No response-time guarantee is currently offered.
